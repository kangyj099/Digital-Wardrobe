# 공통 규칙

## 디자인 원칙

- 학습 최소화, 다양한 상황에서의 편의 제공, 통일되고 일관적인 디자인, 폰트/컬러 소수 고정, 흑백 기피(세련되고 감도 높은 톤), 세로 화면, 반응형
- 스크롤 가능 영역은 그라데이션/여백 등으로 스크롤 가능함을 암시
- 팝업은 반드시 가시적인 닫기 버튼 제공 (우상단 X와 별도 '닫기' 버튼은 동시에 두지 않음)
- **기능 재사용 원칙**: 옷 선택처럼 여러 화면에서 반복되는 기능은 별도로 만들지 않고 기존 화면(옷장)을 그대로 호출해 재사용. 단, 외부 호출 시 제공 기능과 실제 진입 시 기능은 차등을 둠
- **바인딩 뎁스 제한**: 바인딩 생성 체인은 최대 1단계로 제한(선택→만들기→선택→만들기... 방지)
- **미완성/휴지통 항목은 바인딩 불가**: 선택 모달에서 미완성 항목은 배지와 함께 그대로 노출하되 비활성화(회색 처리) 상태로 표시. 터치하면 선택되는 대신 해당 항목의 완성 화면으로 이동. 휴지통항목은 모달에 노출 안 됨
- **갤러리 스크롤 여백**: 갤러리 최상단/최하단 아이템이 겹치는 UI(플로팅 버튼 등)에 가려 일부만 보이지 않도록 해당 아이템이 겹치는 UI의 경계선에 맞춰 완전히 안착할 때까지 스크롤되게 함 (겹치는 UI 높이만큼 상/하단 여백 확보)
- **상시 저장(드래프트 없음)**(Phase 1.5~2 목표)
    
    옷 추가, 코디 만들기 등 편집 화면에 진입해서 중요 데이터를 수정하는 순간 실제 레코드가 즉시 생성되고, 이후 모든 변경이 그 레코드에 계속 저장됨.
    "임시저장/이어하기" 같은 별도 개념 없이, 앱이 강제 종료되거나 사용자가 중간에 나가도 저장된 미완성 항목을 열어 이어서 편집 가능
    
- **미완성 레코드 표시**
    
    메인 갤러리에서 숨기지 않고 "미완성" 배지를 달아 노출
    
- **AI 처리 실패 상태**
    
    자동 마스킹/태깅 등 AI 작업 진행 중 로딩 표시. 타임아웃/오류 시 지수 백오프(1s→2s→4s)로 지정 횟수만큼 자동 재시도.
    모두 실패하면 "{실패 사유} {실패 횟수}회 실패, 다시 시도하시겠어요? [다시 시도]" 팝업 노출
    
- **다크모드 지원**, **사용성**, **접근성**을 고려

## 공통 요소

### 네비게이션

- **상단 헤더** `[현재 컨텐츠 이름 ▾]`
    
    터치시 드롭다운으로 옷장/코디/스타일 일지 중 어디로든 즉시 이동
    (선택 시 해당 카테고리는 항상 루트에서 시작)
    
    헤더에는 카테고리 이름만 두어 가볍게 유지
    
- **뒤로가기**
    
    좌하단(왼손엄지). 이동 스택이 있을 때만 노출, 한 단계씩 이동
    
- **분류 선택 플로팅 버튼**`현재 선택한 분류 기준 ▼ | 현재 보고 있는 분류 ▼`
    
    헤더 바로 아래 배치 (위치는 추후 조정 가능), 옷장/코디처럼 분류가 필요한 화면에서만 노출
    
- **갤러리 메인 화면(옷장/코디/스타일 일지)의 헤더 스타일**
    
    고정 공간을 차지하지 않는 플로팅 오버레이 방식 채택 (iOS 사진 앱 참고).
    
    헤더와 분류 버튼은 배경 반투명 + 블러(프로스티드 글라스) 처리, 텍스트/아이콘은 불투명 유지 — 콘텐츠(옷 목록) 영역을 최대한 확보하면서도 사진 위에서 가독성 저하 없도록 함.
    
    스크롤 시 콘텐츠가 아래 레이어에 흘러가며, 최상단/최하단 스크롤 경계는 "갤러리 스크롤 여백" 원칙 적용
    

### 제스처

| 제스처 | 용도 |
| --- | --- |
| 핀치(오므리기/벌리기) | 갤러리 타일 크기 연속 조절, 이미지 확대/축소 |
| 길게 누르기 | 갤러리 다중 선택 모드 진입, 코디 아트보드에서 옷 길게 누르면 코디 만들기 진입 |
| 좌우 스와이프 | 스타일 일지 카드 슬롯 이동(대표→코디→추가사진) |
| 상하 드래그 | 바텀시트 확장/축소 |
| 아이템 드래그 | 코디 만들기에서 옷 위치 이동, 보드 밖으로 드래그 시 삭제 |

### **분류 기준별 정렬 기준표**

모든 기준에 역순 보기 옵션 제공

| 기준 | 기본 순서 | 사용 컨텐츠 |
| --- | --- | --- |
| 날짜/시간 (최신순) | 내림차순(최신이 위) | 옷장, 코디, 스타일 일지 |
| 옷 종류 | 머리→발 착용순서(모자→상의→아우터→하의→양말→신발→가방/액세서리 등) | 옷장(갤러리 그룹화 기준) / 코디·스타일 일지(항목 내 "사용된 옷 목록" 정렬 기준)* |
| 계절 | 봄가을 → 여름 → 겨울 | 옷장, 코디, 스타일 일지 |
| 색상 | 색상환 기준(세부 색상 순서는 5단계 컬러 팔레트 확정 시 정의) | 옷장 |
| 착용 빈도 | 내림차순(많이 입은 순) | 옷장 |
| 날씨 | 맑음 → 비 → 눈 | 코디, 스타일 일지 |

**※ 옷 종류 기준 적용 범위**

**'옷 종류' 기준은 화면에 따라 적용 범위(스코프)가 다름.**

- **옷장:** 갤러리 자체를 그룹화하는 기준으로 사용
- **코디·스타일 일지:** 갤러리 정렬이 아닌, 각 항목 내부의 **'사용된 옷 목록'** 서브 리스트를 정렬하는 기준으로 사용

※ **날짜, 계절, 날씨, 착용 빈도** 기준은 모두 갤러리 자체의 정렬·그룹화 기준이며, **'옷 종류'만 적용 범위가 다르므로 구현 시 혼동하지 않도록 유의**

## 오프라인 / 데이터 저장 정책

- 코디 등 일부 기능은 비로그인·오프라인 상태에서도 사용 가능
- 자동 배경제거/태깅(AI)은 인터넷 연결 필요 — 연결 안 된 경우 안내 팝업(닫기 + 오늘 그만보기 체크박스) 후 수동 마스킹으로 전환
- 기본은 로컬 저장, 로그인+인터넷 연결 시 클라우드(Firebase)에 저장
- 비로그인 상태에서 로컬 데이터가 일정량 쌓이면 백업을 위해 로그인 유도 안내
- 백업용 데이터 파일 추출/불러오기 지원 (비로그인·오프라인 상태에서도 이어서 사용 가능)
