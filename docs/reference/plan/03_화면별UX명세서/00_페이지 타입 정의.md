# 0. 페이지 타입 정의

공통 속성을 가진 화면들을 타입으로 묶어, 타입 단위로 원칙/기능을 정의. 추후 디자인 컴포넌트 라이브러리와 1:1로 매핑 가능하도록 구성.

## Main형 (옷장 메인 / 코디 메인 / 스타일 일지 메인 / 휴지통)

- 플로팅 오버레이 헤더(블러+반투명 배경), 갤러리 스크롤 여백/힌트 원칙 적용
- 두 가지 변형: **그룹형**(옷장/코디 — 분류 기준별 그룹 드릴다운) vs **플랫+필터형**(스타일 일지, 휴지통 — 그룹 없이 필터 칩만)
    - (Phase 2~3 검토) 코디·스타일 일지에 "사용자 지정 그룹(폴더)" 변형 추가 가능성 있음 — 폴더 CRUD/소속관리 UI가 필요한 별도 규모의 기능이라 지금은 설계하지 않고 후보로만 남겨둠
- 분류 선택 플로팅 버튼: 그룹형 화면에서만 노출
- [+] 버튼: 상황(전체보기/특정 분류)에 따라 라벨 전환 (휴지통은 [+] 버튼 없음 — 추가 개념이 없는 화면)
- 우상단 [선택] 버튼 또는 길게 누르기 → 다중 선택 모드 → 하단 액션바(삭제/복원 등)
- 미완성 레코드는 배지로 노출(숨기지 않음)

**휴지통의 추가 확장 요소** (Main형 공통 요소 위에 얹는 화면 전용 요소, 일반화하지 않음)

- 옷장/코디처럼 그룹화 계층+상징적 타일이 있는 그리드가 아니라, **아이폰 사진 앱의 "최근 삭제됨"처럼 순수 썸네일 타일 그리드**(제목 텍스트 없이 이미지 중심)
- 각 타일: 유형 표시 아이콘 배지 + "N일"(영구 삭제까지 남은 일수) 텍스트, 썸네일 위 오버레이로 노출
- 화면 상단 비우기 버튼 — 파괴적 액션이라 강한 확인 모달 필요
- **타일 터치 시 다른 Main형 화면들과 달리 상세 페이지로 전환되지 않고, 정보 팝업이 뜸** (아래 5번 섹션 참고) — 개별 항목의 복원/영구삭제는 이 팝업에서 처리하므로 행/타일 단위의 별도 스와이프 단축 액션은 두지 않음(다중 선택 모드는 여러 개를 한 번에 처리할 때만 사용)

## Detail형 (옷 상세 / 코디 상세 / 스타일 일지 열람)

- 공용 네비게이션(헤더 드롭다운 + 좌하단 조건부 뒤로가기)
- 헤더 "⋯" 메뉴 → 삭제
- 다른 컨텐츠로의 상호 참조 링크(히스토리, 연결된 항목)

## Add/Create형 (옷 추가하기 / 코디 만들기 / 스타일 일지 추가)

- 상시 저장(드래프트 없음) — 진입 즉시 레코드 생성
- 저장 버튼 위치는 화면 구조에 따라 다름 (아래 각 화면 참고, 스크롤 폼형은 하단 버튼이 더 표준적)
- "?" 코치마크 도움말 아이콘(코디 만들기/옷 추가하기)
- 진행 중 화면 이탈에 대한 별도 확인 절차 불필요(상시 저장 원칙)

## Modal/Sheet형 (옷장 선택 모달, 코디/스타일 일지 선택 모달)

- 기능 재사용 원칙: 별도 화면을 새로 만들지 않고 기존 메인 화면을 모달로 재호출
- 외부 호출 시 제공 기능과 네이티브 진입 시 기능은 차등
- 바인딩 뎁스 제한 적용 대상

## Utility형 (설정)

- 리스트-로우 패턴(토글/체브론), 파괴적 액션은 스와이프 또는 별도 확인 절차로 한 단계 더 진입
