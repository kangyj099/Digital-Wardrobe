# 5. 삭제 & 휴지통 (Main형, 플랫+필터 변형)

**두 가지 다른 "삭제" 개념 구분**

- **연결 해제(Unlink)**: 코디 아트보드에서 옷을 빼거나, 스타일 일지에서 코디 슬롯을 비우는 것.
- **삭제(Delete)**: 옷/코디/스타일 일지 레코드 자체를 지우는 것. 삭제 시스템은 “논리 삭제 → 휴지통 → 영구 삭제” 3단계 상태를 가짐. 아래 규칙 적용

**삭제 진입점**

- 상세 화면(옷 상세/코디 상세/스타일 일지 열람): 헤더의 "⋯"(더보기) 아이콘 → 메뉴에 [삭제]
- 메인 갤러리: 우상단 [선택] 버튼 또는 항목 길게 누르기 → 다중 선택 모드 → 하단 액션바 [삭제]

**동작**: 되돌릴 수 있어 확인 모달 없이 즉시 휴지통으로 이동 + 토스트("휴지통으로 이동됨 · 실행취소")

**삭제 대기 상태**: `is_deleted`플래그만 세팅, 다른 곳 참조는 평소처럼 정상 노출(복원 시 즉시 반영)

**휴지통 화면**: 설정(Settings) 내부에 위치(헤더 드롭다운엔 미포함)

옷/코디/스타일 일지 통합 갤러리 + 필터 칩(`전체 | 옷 | 코디 | 스타일 일지`).

아이폰 사진 앱 "최근 삭제됨"처럼 순수 썸네일 타일 그리드로 표시(리스트 행이 아님).

각 타일에는 유형 표시 아이콘 배지와 "N일"(영구 삭제까지 남은 일수) 텍스트가 썸네일 위 오버레이로 노출

- 우상단 [선택] 버튼 또는 항목 길게 누르기로 다중 선택 모드 진입 → 하단에 [복원] [영구 삭제] 플로팅 버튼 노출
- 화면 상단에 [비우기] 버튼(전체 일괄 영구 삭제) — 가장 파괴적인 동작이라 강한 확인 모달 필요: "전체 {N}개 항목을 영구 삭제하시겠어요? 되돌릴 수 없어요" [취소] [비우기]
- 개별/다중 [영구 삭제]도 일반 삭제와 달리 되돌릴 수 없으므로 확인 모달 필요: "영구 삭제하면 되돌릴 수 없어요, 계속할까요?"

**타일 터치 시 동작**: 다른 Main형 화면과 달리 상세 페이지로 전환되지 않고 **정보 팝업**이 뜸

- 팝업 상단: 컨텐츠 유형 표시(옷/코디/스타일 일지), 우측 모서리 닫기 버튼
- 헤더 아래: 이미지 배치
- 이미지 안쪽 중앙 하단: "N일"(영구 삭제까지 남은 일수) 오버레이
- 헤더-이미지 사이 또는 이미지 아래: 제작된 날짜/시간 표기(삭제일이 아닌 생성일)
- 팝업 하단: [복원] [영구 삭제] 버튼 — 팝업 내용이 길어 스크롤이 생기더라도 이 버튼들은 스크롤 위치와 무관하게 항상 화면 하단에 고정 노출. [영구 삭제] 선택 시 위와 동일한 확인 모달 노출

**자동 영구 삭제**: 15일 경과 시 자동(앱 실행 시 클라이언트 체크, 별도 서버 스케줄러 불필요). 이때 다른 참조는 조용히 제거(고스트 placeholder 없음)

## **옷 삭제 시 코디 캐스케이드 처리**

- 핵심 아키텍처: 코디는 저장 시마다 평면 렌더링 스냅샷 이미지 저장. 목록/상세는 항상 스냅샷 사용(참조 아이템 삭제돼도 안 깨짐). 라이브 데이터 정리는 "편집 진입" 시점에만 발생
- 옷 삭제 시 사용 코디가 1개 이상이면 안내 팝업: "이 옷은 {N}개의 코디에 사용되고 있어요. 삭제하면 휴지통으로 이동하고, 각 코디는 다음 편집 시 자동으로 제거돼요. [취소] [휴지통으로 이동]"
- 코디 목록: 삭제된 옷 포함 코디는 타일에 작은 배지(연결끊김 아이콘, 차분한 톤)
- 코디 상세: 스냅샷 그대로 표시 + 안내 문구("다음 편집 시 자동 정리"), 사용된 옷 목록엔 "삭제됨" 회색 placeholder 칩
- 편집 진입 시: 확인 팝업("삭제된 옷 {N}개 포함, 편집 시작 시 자동 제거") → 진행 시 제거된 채로 진입(즉시 저장+스냅샷 재생성)
- 정리 후 0개 남으면 별도 "빈 코디" 상태 새로 만들지 않고 기존 "미완성" 처리 재사용(예측 가능성+구현 단순성 모두 만족)
