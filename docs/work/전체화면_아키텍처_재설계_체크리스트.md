# 전체 화면 아키텍처 재설계 — 세부 체크리스트

## 배경 (2026-07-12, 이 세션에서 발견)

옷장 메인 화면에 하단 좌측 뒤로가기 버튼(`_FrostedBackButton`, 커밋 `31b42b0`)을 추가하고, 이어서 미구현 placeholder 화면들(`_placeholder` 헬퍼, `lib/router/app_router.dart`)에 임시 AppBar 뒤로가기를 추가하는 작업을 진행하던 중, 사용자가 다음을 지적함:

- "뒤로가기 버튼과 옷장/코디/스타일일지 전환 토글 버튼은 조건 충족시 **모든 화면에서 공통적으로 나타나길 바라는, 앱을 관통하는 UI**"
- 지금까지의 작업 방식(Task 8~15를 화면 하나씩 순서대로 구현)은 이 전제를 반영하지 않고 있었음 — 옷장 메인 화면 하나에만 뒤로가기 버튼을 심었고, 카테고리 토글도 옷장 메인에만 있음.
- 원본 스프린트 플랜(`docs/superpowers/plans/2026-07-08-flutter-frontend-hifi-screens.md`)의 Task 8~15는 화면별로 독립적으로 짜여 있어, 화면을 관통하는 공용 UI 요구사항이 태스크 분해에 반영돼 있지 않을 가능성이 큼.

## 사용자가 확정한 규칙 (2026-07-12)

1. **뒤로가기 버튼**: 조건(`canPop()` 등 뒤로 갈 곳이 있는지) 충족 시 **모든 화면**에서 항상 표시돼야 함. 옷장 메인만의 특수 기능이 아니라 앱 전역 공통 UI.
2. **카테고리 토글(옷장/코디/스타일일지 전환)**: **코디 만들기(에디터), 옷 추가하기, 스타일일지 추가하기 3개 화면을 제외한 모든 화면**에서 표시돼야 함. (이전 세션의 "메인 화면 3개에만 필요하다"는 판단은 사용자에 의해 정정됨 — 상세/열람 화면 등에도 필요.)
3. **그룹형(Grouped) 드릴다운**: 각 도메인의 **'메인' 화면**(옷장 메인/코디 메인/스타일일지 메인)에서 표시돼야 함. (옷장 메인 체크리스트에 이미 설계 스케치 있음 — `docs/work/옷장메인_재설계_체크리스트.md`의 "오늘 스코프 밖으로 명시적으로 미룬 것 > 그룹형 드릴다운 아키텍처" 참고, 코디/스타일일지 메인도 동일 패턴 적용 검토 필요.)

## 다음 세션에서 할 일

1. **`docs/reference/plan/03_화면별UX명세서/` 전체를 다시 정독**하고, 화면별로 위 3개 규칙(뒤로가기/카테고리 토글/그룹형 드릴다운) 적용 여부를 표로 정리한다. `00_페이지 타입 정의.md`도 함께 확인(그룹형/플랫형 등 페이지 타입 정의가 이미 있음 — 옷장메인 체크리스트가 이걸 언급한 바 있음).
2. **전체 화면을 조망하는 프론트엔드 작업 설계**를 다시 한다 — 화면 하나씩 순서대로 짜는 대신, 공용 쉘/컴포넌트(뒤로가기, 카테고리 토글, 그룹형 드릴다운)를 먼저 설계하고 각 화면이 그걸 소비하는 구조로 Task를 재산정한다. 이 작업은 아키텍처 결정이 크므로 **`superpowers:brainstorming`** 스킬로 시작해서 방향을 잡고, 필요하면 **`superpowers:writing-plans`**로 플랜을 다시 쓰는 게 적절해 보임(CLAUDE.md의 스킬 우선순위 규칙 — 창작/설계 작업 전 brainstorming 먼저).
3. 원본 플랜(`docs/superpowers/plans/2026-07-08-flutter-frontend-hifi-screens.md`)의 Task 8~15는 그대로 유효하지 않을 수 있음 — 재산정 후 이 플랜 문서 자체를 갱신하거나 대체할 필요가 있는지 판단.
4. 기존에 이미 커밋된 것들과의 정합성 확인 필요:
   - 옷장 메인의 `_FrostedBackButton`(커밋 `31b42b0`)은 원래 "옷장 메인 자체의 미래 드릴다운" 용도로 좁게 스코프됐었는데, 이제 전역 공용 컴포넌트로 다시 설계될 가능성이 큼 — 재사용/교체 여부 결정 필요.
   - 카테고리 토글은 현재 `ClosetMainScreen._buildCategoryDropdown`에 로컬로 구현돼 있음(다른 화면과 공유 안 됨) — 공용 위젯으로 추출 필요.
