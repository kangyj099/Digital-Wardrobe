## 요청받았으나 미착수

- **컬러 팔레트를 실제로 Palette 1 또는 2로 전환** — `lib/theme/app_colors.dart`의 `activePalette` 상수를 `ColorPalette.palette1`/`.palette2`로 바꾸기만 하면 됨(구조는 이미 완료). 어느 팔레트를 쓸지 사용자 최종 확정 필요.

## 후속 필요 (뒤로가기 버튼 Review P2, 비차단이라 그대로 진행했음)

- **프로스티드글래스 톤 값이 `OverlayHeader`와 별개 리터럴로 중복** — 값 자체는 일치하지만 공유 상수/빌더로 뽑혀있지 않아, 헤더 톤이 나중에 바뀌면 이 버튼만 조용히 어긋날 수 있음. 세 번째 소비자가 생기기 전에 추출 권장.
- **Safe-area 미처리** — 우측 FAB는 `Scaffold.floatingActionButton`이 자동으로 safe-area를 감안하지만, 이 버튼은 body `Stack` 안 raw `Positioned`라 노치/제스처바 기기에서 FAB와 하단 여백이 어긋날 수 있음. 코드베이스 전체에 `SafeArea`가 아직 안 쓰이고 있는 기존 공백이지만, 상호작용 가능한 하단 요소로는 이번이 처음이라 체감되는 지점.

## 미착수 (Task 4)

- **ExpandableSearchField**: 우측 원형 "◎" 버튼 → 캡슐형 검색창으로 모핑. `AnimatedContainer`, 250~350ms(`AppMotion.searchExpand`=300ms 이미 정의됨), `FocusNode`+`TextEditingController`, 검색어는 Provider에 보관(컨텍스트 보존). 실제 텍스트 필터링 로직은 이번 스코프 아님(UI 모핑+포커스 흐름까지만).
- **HUD 스타일 스크롤바**: `RawScrollbar` 기반, 평소 숨김/스크롤 중에만 우측 얇게 노출, 빠른 fade-in(~100ms)/~0.9초 후 fade-out. 다른 갤러리 화면(코디/스타일일지)에도 재사용 가능하게 `lib/widgets/hud_scrollbar.dart`로 분리.

## 오늘 스코프 밖으로 명시적으로 미룬 것 (별도 착수 시 참고)

### 그룹형(Grouped) 드릴다운 아키텍처

디자인 문서(`docs/reference/plan/03_화면별UX명세서/00_페이지 타입 정의.md` L3)엔 옷장이 "그룹형"(분류 기준별 그룹 타일 오버뷰 → 탭해서 드릴다운)으로 정의돼 있는데, 지금 구현은 "플랫+필터"(계절 선택 시 바로 플랫 리스트)다. 착수 시 설계 스케치:

```dart
enum ClosetGroupCriterion { season } // 향후 category, color, wearFrequency 등 확장 가능
enum ClosetViewMode { groupOverview, allFlat, drilledInto }
// closetViewModeProvider, closetDrilledSeasonProvider, closetGroupedOverviewProvider(Map<Season, List<ClothingItem>>) 신설
```

- 화면 진입 기본 = `groupOverview`(계절별 그룹 타일).
- 그룹 타일 탭 → `drilledInto`(해당 계절 플랫 리스트).
- 계절 드롭다운에서 "전체보기" → `allFlat` 직접 전이.
- 뒤로가기 버튼(위 항목) → `groupOverview`로 복귀.
- 이 아키텍처가 들어가면 위 "하단 좌측 뒤로가기 버튼"도 실제 스택 의미를 갖게 됨(지금은 `canPop()` 기반 임시 구현).

### 제스처 통합

핀치 리사이즈(그리드 밀도 3단계로 스냅), 롱프레스 다중선택 진입, 두 제스처 충돌 해소(A11 접근성 규칙 — 핀치 시작되면 롱프레스 타이머 취소). 밀도 전환은 현재 버튼으로만 제공 중(핀치의 비제스처 대안으로 이미 충분 — A4 규칙 만족).

### 선택모드/삭제 플로우

하단 삭제바, 체크서클 렌더링, 삭제→휴지통 이동, undo 토스트(Design Principles의 C7 UndoableActionToast 패턴 — 전역/영속 상태 필요). `ClosetItemsNotifier.softDelete`는 이미 존재, `SelectableGalleryTile.selected` prop도 이미 있어 확장 시 기존 구조를 갈아엎을 필요 없음.
