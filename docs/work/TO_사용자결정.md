## 옷장/코디 분류 기준 정렬의 "오름차순" 의미 (2026-07-19, 플랜 작성 중 발견)

**배경**: `docs/superpowers/specs/2026-07-19-main-header-classification-and-settings-entry-design.md` §3.2가
"기본 정렬 순서" 표(옷종류=머리→발, 계절=봄가을→여름→겨울, 날씨=맑음→비→눈 등)를 명시하지만,
§3.6의 `closetSortAscendingProvider`/`compositionSortAscendingProvider` 기본값(`false`)에 대한
스펙 원문 주석은 "기본 내림차순(최신/많이입은순)"만 언급하고 옷종류/계절/날씨 케이스는 다루지
않습니다. 두 조항을 문자 그대로 조합하면(ascending=false를 "index 내림차순"으로 해석) 옷종류/
계절/날씨의 기본 표시가 표와 정반대(발→머리, 겨울→여름→봄가을, 눈→비→맑음)가 됩니다.

**이 플랜(`docs/superpowers/plans/2026-07-19-classification-drilldown-and-settings-entry.md`
Task 3/4)이 잠정 채택한 해석**: `ascending` 토글의 "false(기본)"은 항상 §3.2 표의 순서와
일치하도록 정의합니다 — 옷종류/계절/날씨는 정렬 시 index를 반전해서 넘기고(`ascending: !ascending`),
날짜/착용빈도는 그대로 자연스러운 방향(true=오름차순)을 씁니다. 즉 토글을 안 건드리면 항상
§3.2 표대로 보이고, 토글하면 반대 방향이 됩니다.

**확인해 주실 것**:
- 이 해석(기준마다 "기본이 항상 표와 일치"하도록 방향을 다르게 매핑)이 의도에 맞는지, 또는
- 더 단순하게 "ascending=true가 항상 index 오름차순"이라는 하나의 전역 규칙을 원하시는지
  (그러면 옷종류/계절/날씨 기본 표시가 발→머리/겨울→여름→봄가을/눈→비→맑음이 됩니다 — 표와 반대).

그걸 보고 판단하셔도 됩니다. 확정되면 이 항목(또는 파일 전체)을 삭제해 주세요.
