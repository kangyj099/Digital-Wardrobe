디자인 단계에서 직접 판단할 항목(옷장/코디 시각적 구분, 옷 상세의 코디·스타일 일지 타일 통합 여부)은 제외.

# 공통 규칙

## 디자인 원칙

- 학습 최소화, 다양한 상황에서의 편의 제공, 통일되고 일관적인 디자인, 폰트/컬러 소수 고정, 흑백 기피(세련되고 감도 높은 톤), 세로 화면, 반응형
- 스크롤 가능 영역은 그라데이션/여백 등으로 스크롤 가능함을 암시
- 팝업은 반드시 가시적인 닫기 버튼 제공 (우상단 X와 별도 '닫기' 버튼은 동시에 두지 않음)
- **기능 재사용 원칙**: 옷 선택처럼 여러 화면에서 반복되는 기능은 별도로 만들지 않고 기존 화면(옷장)을 그대로 호출해 재사용. 단, 외부 호출 시 제공 기능과 실제 진입 시 기능은 차등을 둠
- **바인딩 뎁스 제한**: 바인딩 생성 체인은 최대 1단계로 제한(선택→만들기→선택→만들기... 방지)
- **미완성/휴지통 항목은 바인딩 불가**: 선택 모달에서 미완성 항목은 배지와 함께 그대로 노출하되 비활성화(회색 처리) 상태로 표시. 터치하면 선택되는 대신 해당 항목의 완성 화면으로 이동. 휴지통항목은 모달에 노출 안 됨
- **갤러리 스크롤 여백**: 갤러리 최상단/최하단 아이템이 겹치는 UI(플로팅 버튼 등)에 가려 일부만 보이지 않도록 해당 아이템이 겹치는 UI의 경계선에 맞춰 완전히 안착할 때까지 스크롤되게 함 (겹치는 UI 높이만큼 상/하단 여백 확보)
- **상시 저장(드래프트 없음)**(Phase 1.5~2 목표)
    
    옷 추가, 코디 만들기 등 편집 화면에 진입해서 중요 데이터를 수정하는 순간 실제 레코드가 즉시 생성되고, 이후 모든 변경이 그 레코드에 계속 저장됨.
    "임시저장/이어하기" 같은 별도 개념 없이, 앱이 강제 종료되거나 사용자가 중간에 나가도 저장된 미완성 항목을 열어 이어서 편집 가능
    
- **미완성 레코드 표시**
    
    메인 갤러리에서 숨기지 않고 "미완성" 배지를 달아 노출
    
- **AI 처리 실패 상태**
    
    자동 마스킹/태깅 등 AI 작업 진행 중 로딩 표시. 타임아웃/오류 시 지수 백오프(1s→2s→4s)로 지정 횟수만큼 자동 재시도.
    모두 실패하면 "{실패 사유} {실패 횟수}회 실패, 다시 시도하시겠어요? [다시 시도]" 팝업 노출
    
- **다크모드 지원**, **사용성**, **접근성**을 고려

## 공통 요소

### 네비게이션

- **상단 헤더** `[현재 컨텐츠 이름 ▾]`
    
    터치시 드롭다운으로 옷장/코디/스타일 일지 중 어디로든 즉시 이동
    (선택 시 해당 카테고리는 항상 루트에서 시작)
    
    헤더에는 카테고리 이름만 두어 가볍게 유지
    
- **뒤로가기**
    
    좌하단(왼손엄지). 이동 스택이 있을 때만 노출, 한 단계씩 이동
    
- **분류 선택 플로팅 버튼**`현재 선택한 분류 기준 ▼ | 현재 보고 있는 분류 ▼`
    
    헤더 바로 아래 배치 (위치는 추후 조정 가능), 옷장/코디처럼 분류가 필요한 화면에서만 노출
    
- **갤러리 메인 화면(옷장/코디/스타일 일지)의 헤더 스타일**
    
    고정 공간을 차지하지 않는 플로팅 오버레이 방식 채택 (iOS 사진 앱 참고).
    
    헤더와 분류 버튼은 배경 반투명 + 블러(프로스티드 글라스) 처리, 텍스트/아이콘은 불투명 유지 — 콘텐츠(옷 목록) 영역을 최대한 확보하면서도 사진 위에서 가독성 저하 없도록 함.
    
    스크롤 시 콘텐츠가 아래 레이어에 흘러가며, 최상단/최하단 스크롤 경계는 "갤러리 스크롤 여백" 원칙 적용

| 제스처 | 용도 |
| --- | --- |
| 핀치(오므리기/벌리기) | 갤러리 타일 크기 연속 조절, 이미지 확대/축소 |
| 길게 누르기 | 갤러리 다중 선택 모드 진입, 코디 아트보드에서 옷 길게 누르면 코디 만들기 진입 |
| 좌우 스와이프 | 스타일 일지 카드 슬롯 이동(대표→코디→추가사진) |
| 상하 드래그 | 바텀시트 확장/축소 |
| 아이템 드래그 | 코디 만들기에서 옷 위치 이동, 보드 밖으로 드래그 시 삭제 |

### **분류 기준별 정렬 기준표**

모든 기준에 역순 보기 옵션 제공

| 기준 | 기본 순서 | 사용 컨텐츠 |
| --- | --- | --- |
| 날짜/시간 (최신순) | 내림차순(최신이 위) | 옷장, 코디, 스타일 일지 |
| 옷 종류 | 머리→발 착용순서(모자→상의→아우터→하의→양말→신발→가방/액세서리 등) | 옷장(갤러리 그룹화 기준) / 코디·스타일 일지(항목 내 "사용된 옷 목록" 정렬 기준)* |
| 계절 | 봄 → 여름 → 가을 → 겨울 | 옷장, 코디, 스타일 일지 |
| 색상 | 색상환 기준(세부 색상 순서는 5단계 컬러 팔레트 확정 시 정의) | 옷장 |
| 착용 빈도 | 내림차순(많이 입은 순) | 옷장 |
| 날씨 | 맑음 → 비 → 눈 | 코디, 스타일 일지 |

**※ 옷 종류 기준 적용 범위**

**'옷 종류' 기준은 화면에 따라 적용 범위(스코프)가 다름.**

- **옷장:** 갤러리 자체를 그룹화하는 기준으로 사용
- **코디·스타일 일지:** 갤러리 정렬이 아닌, 각 항목 내부의 **'사용된 옷 목록'** 서브 리스트를 정렬하는 기준으로 사용

※ **날짜, 계절, 날씨, 착용 빈도** 기준은 모두 갤러리 자체의 정렬·그룹화 기준이며, **'옷 종류'만 적용 범위가 다르므로 구현 시 혼동하지 않도록 유의**

## 오프라인 / 데이터 저장 정책

- 코디 등 일부 기능은 비로그인·오프라인 상태에서도 사용 가능
- 자동 배경제거/태깅(AI)은 인터넷 연결 필요 — 연결 안 된 경우 안내 팝업(닫기 + 오늘 그만보기 체크박스) 후 수동 마스킹으로 전환
- 기본은 로컬 저장, 로그인+인터넷 연결 시 클라우드(Firebase)에 저장
- 비로그인 상태에서 로컬 데이터가 일정량 쌓이면 백업을 위해 로그인 유도 안내
- 백업용 데이터 파일 추출/불러오기 지원 (비로그인·오프라인 상태에서도 이어서 사용 가능)

## 0. 페이지 타입 정의

공통 속성을 가진 화면들을 타입으로 묶어, 타입 단위로 원칙/기능을 정의. 추후 디자인 컴포넌트 라이브러리와 1:1로 매핑 가능하도록 구성.

### Main형 (옷장 메인 / 코디 메인 / 스타일 일지 메인 / 휴지통)

- 플로팅 오버레이 헤더(블러+반투명 배경), 갤러리 스크롤 여백/힌트 원칙 적용
- 두 가지 변형: **그룹형**(옷장/코디 — 분류 기준별 그룹 드릴다운) vs **플랫+필터형**(스타일 일지, 휴지통 — 그룹 없이 필터 칩만)
    - (Phase 2~3 검토) 코디·스타일 일지에 "사용자 지정 그룹(폴더)" 변형 추가 가능성 있음 — 폴더 CRUD/소속관리 UI가 필요한 별도 규모의 기능이라 지금은 설계하지 않고 후보로만 남겨둠
- 분류 선택 플로팅 버튼: 그룹형 화면에서만 노출
- [+] 버튼: 상황(전체보기/특정 분류)에 따라 라벨 전환 (휴지통은 [+] 버튼 없음 — 추가 개념이 없는 화면)
- 우상단 [선택] 버튼 또는 길게 누르기 → 다중 선택 모드 → 하단 액션바(삭제/복원 등)
- 미완성 레코드는 배지로 노출(숨기지 않음)

**휴지통의 추가 확장 요소** (Main형 공통 요소 위에 얹는 화면 전용 요소, 일반화하지 않음)

- 옷장/코디처럼 그룹화 계층+상징적 타일이 있는 그리드가 아니라, **아이폰 사진 앱의 "최근 삭제됨"처럼 순수 썸네일 타일 그리드**(제목 텍스트 없이 이미지 중심)
- 각 타일: 유형 표시 아이콘 배지 + "N일"(영구 삭제까지 남은 일수) 텍스트, 썸네일 위 오버레이로 노출
- 화면 상단 비우기 버튼 — 파괴적 액션이라 강한 확인 모달 필요
- **타일 터치 시 다른 Main형 화면들과 달리 상세 페이지로 전환되지 않고, 정보 팝업이 뜸** (아래 5번 섹션 참고) — 개별 항목의 복원/영구삭제는 이 팝업에서 처리하므로 행/타일 단위의 별도 스와이프 단축 액션은 두지 않음(다중 선택 모드는 여러 개를 한 번에 처리할 때만 사용)

### Detail형 (옷 상세 / 코디 상세 / 스타일 일지 열람)

- 공용 네비게이션(헤더 드롭다운 + 좌하단 조건부 뒤로가기)
- 헤더 "⋯" 메뉴 → 삭제
- 다른 컨텐츠로의 상호 참조 링크(히스토리, 연결된 항목)

### Add/Create형 (옷 추가하기 / 코디 만들기 / 스타일 일지 추가)

- 상시 저장(드래프트 없음) — 진입 즉시 레코드 생성
- 저장 버튼 위치는 화면 구조에 따라 다름 (아래 각 화면 참고, 스크롤 폼형은 하단 버튼이 더 표준적)
- "?" 코치마크 도움말 아이콘(코디 만들기/옷 추가하기)
- 진행 중 화면 이탈에 대한 별도 확인 절차 불필요(상시 저장 원칙)

### Modal/Sheet형 (옷장 선택 모달, 코디/스타일 일지 선택 모달)

- 기능 재사용 원칙: 별도 화면을 새로 만들지 않고 기존 메인 화면을 모달로 재호출
- 외부 호출 시 제공 기능과 네이티브 진입 시 기능은 차등
- 바인딩 뎁스 제한 적용 대상

### Utility형 (설정)

- 리스트-로우 패턴(토글/체브론), 파괴적 액션은 스와이프 또는 별도 확인 절차로 한 단계 더 진입

## 1. 옷장

### 옷장 메인/목록 (Main형)

- 두 손가락 핀치 제스처로 갤러리 타일 크기 조절 + 분류 버튼 오른쪽 타일 크기 전환 버튼
    
    버튼 아이콘은 탭할 때마다 큰 정사각 1열 → 2×2 → 4×4 아이콘으로 순환하지만, 이는 밀도 단계를 상징하는 아이콘일 뿐 실제 컬럼 수는 최소-중간-최대 3단계로 매핑됨(구체적 컬럼 개수는 디자인 원칙 문서에서 정의)
    
- 상단 플로팅바: `현재 선택한 분류 기준 ▼ | 현재 보고 있는 분류 ▼` (분류 기준이 '전체 보기'면 두 번째 버튼 숨김)
- 분류 그룹 클릭 → 목록 진입, 분류 기준 바꾸면 그룹 보기로 복귀
- 우하단 [+] 버튼: 전체보기에서는 [한 장 추가하기 / 여러 장 추가하기], 특정 분류를 보는 중엔 [이 분류에 한 장 추가하기 / 이 분류에 여러 장 추가하기]로 라벨 전환 (자동 태그 적용)
- 옷 터치 시 약간의 반응 애니메이션 후 상세 화면 전환
- 텍스트 검색, 정렬 옵션(최신순/착용빈도순 등) 지원

### 옷 추가하기 (Add/Create형)

- 갤러리에서 사진 선택. 이미 앱에 등록 완료한 사진은 시각적으로 표시(딤 처리 등)
- **한 장 추가하기**: 이미지 편집기(자르기/회전/확대축소/마스킹 붓) + 자동 마스킹 버튼(상단 중앙) → 배경 제거 후 자동 중앙 크롭
    - 필드 입력 단계에서는 옷 이미지가 상단에 고정되고, 그 아래로 필드들이 스크롤됨.
    이미지 영역 우하단에 편집 아이콘을 두어 필드 입력 중에도 언제든 이미지 편집으로 재진입 가능
    - 기본 필드(종류/색상/사이즈/계절/위치/메모) 노출, [정보 추가]로 브랜드/구매처/구매가 추가
    - 자동 태깅된 대표 태그는 수정 가능, 내부 메타데이터는 비공개
    - 우상단 V버튼 또는 하단 [옷 추가 완료] 버튼으로 저장
    - 저장 후 옷장으로 복귀 애니메이션, 추가한 옷이 있는 위치로 자동 스크롤
- **여러 장 한 번에 추가하기**: 여러 사진 선택 → 자동 배경제거+자동태그로 일괄 저장 → 이후 개별 수정 가능. 진행률 모달(프로그레스바), 중간 취소 시 완료분까지만 유지
- 헤더에 "?" 아이콘 → 코치마크 팝오버(MVP), [자세히 보기] → 가이드 워크스루 패널(Phase 3)

### 옷 상세 (Detail형)

- 상단 이미지 (핀치 확대/축소, 터치 시 전체화면)
- 하단 주요 태그(접힘/더보기), 위치/메모
- 코디·스타일 일지 히스토리 (디자인 단계에서 통합/분리 방식 결정)
- 착용 카운트, 마지막 착용일 표시
- 삭제 시 확인 절차 + 임시 휴지통

## 2. 코디 (가상 조합)

### 코디 메인 (Main형)

- 옷장과 동일한 레이아웃/버튼 패턴 (분류 그룹화, 핀치 줌 등)
- 우하단 [+] 버튼: 옵션 없이 바로 코디 만들기로 진입 (1개씩만 생성)
- 특정 분류를 보고 있을 때 + → 해당 분류 태그 자동 적용, 라벨 [이 분류로 코디 만들기]로 전환
- 기본 1:1 아트보드 (변경 가능성 있음),  정렬/필터에 날씨·계절 기준 지원(스타일 일지와 공통)

> (Phase 2) 기존 코디를 레퍼런스로 삼아 새 코디를 만드는 편의 기능
> 

### 코디 상세 (Detail형)

- 상단 아트보드: 계절/날씨/태그/분류 표시, 공란은 [+] 버튼으로 대체되며 즉시 수정 가능
- 아트보드에서 옷이 겹친 영역 터치 → 대상 선택 팝업 → 선택한 옷 영역에 상호작용 반영
- 아트보드의 옷 터치 → 하단 옷 목록에서 해당 옷 위치로 스크롤 + 강조 표시 (테두리 등)
- 아트보드의 옷 길게 누르기(1~2초) → 코디 만들기(편집) 화면 진입
- 하단: 사용된 옷 목록(가로 스크롤) → 연결된 스타일 일지 목록(2열, 스타일 일지 1개면 2칸 확대 배치)
- 연결된 스타일 일지 없으면 [+] 슬롯 → 스타일 일지 리스트 모달(하단 시트, 옷장 모달과 동일 작동 방식). 여기서 새 스타일 일지를 만들 수도 있는데(1단계 바인딩), 그렇게 만들어진 스타일 일지의 코디 슬롯은 **선택만 가능**하고 새로 만들 수는 없음(바인딩 뎁스 제한)
- **자동 매칭(초기 세팅용, 지속 동기화 아님)**: 코디를 스타일 일지에 연결하면, 그 코디에 포함된 옷들이 스타일 일지의 착용 옷 목록에 자동 추가(중복 제외). 반대로 스타일 일지에 이미 등록된 착용 옷이 있는 상태에서 새 코디를 만들면, 그 옷들이 새 코디 아트보드에 기본 그리드 배치로 미리 올라간 채 시작 (이후 자유롭게 재배치/삭제 가능)
- 헤더 "⋯" 메뉴 → 삭제

### 코디 만들기 (편집) (Add/Create형, 편집)

- 상단바: 취소(좌) / **코디 이름 입력 필드** (중앙, 기존 "코디 만들기" 텍스트 위치) / 저장 V버튼(우)
    - 진입 시 흐린 색 플레이스홀더 "코디 이름" 노출, 공란이 되면 언제든 재노출
    - 미포커스 상태에서 텍스트가 넘치면 말줄임(...), 터치해 포커스하면 박스가 가로/세로로 확장되어 전체 내용 표시(자동 줄바꿈, 개행 직접 입력은 불허)
    - 공백/특수문자 허용, 최대 40자 (근접 시 카운터 노출 권장)
    - 미입력 상태로 저장 시 "YYYY-MM-DD 시:분:초"로 자동 지정
- 상단 1:1 아트보드 고정, 하단은 옷장 갤러리를 팝업 시트로 배치
    - **바텀시트 기본 크기**: 키패드 정도의 중간 높이로 시작 (충분히 스크롤 가능)
    - 옷을 하나 추가하면 자동으로 얇은 핸들바 상태로 접힘 (편집에 방해되지 않게), 핸들바를 위로 드래그하면 재확장
    - 완전히 접힌 상태에서는 위쪽 꺾쇠(∧) + 옷 아이콘으로 "당기면 옷 목록이 열린다"는 것을 암시 (하이파이 단계에서 적용)
- 옷장 모달에서 옷 추가도 가능, 추가한 옷은 자동으로 아트보드에 선택 배치
- **아트보드 모서리에 배경색 스와치 컨트롤** (현재 배경색 표시, 터치 시 변경) — 바텀시트(추가할 아이템)와 역할을 분리: "추가하는 것"은 시트에서, "보드 자체 설정"은 보드에서. MVP는 흰색/회색/검은색 단색만 지원
    - (Phase 2) 스티커 등 꾸밈요소 추가 시, 바텀시트에 [옷 | 스티커] 탭 도입 예정. 꾸밈요소는 하단 "사용된 옷 목록" 스트립에는 노출하지 않음(옷만 노출). 삭제는 보드 밖으로 드래그 또는 별도 숨겨진 레이어 리스트로 관리 (검토 필요)
- 아트보드 아이템: 이동, 회전, 크기 변경, 렌더순서(z-index) 변경
- 렌더순서 변경: 겹친 영역 터치 → 컨텍스트 메뉴(팝업)로 겹친 이미지 리스트 → 드래그로 순서 재배열
- 겹친 이미지 이동 시 기본은 최상단 옷, 아래쪽 옷은 컨텍스트 메뉴에서 선택 후 터치+드래그
- **하단 "사용된 옷 목록" 영역**: 고정 높이의 그리드(4열, 기본 2줄 노출) 안에서 세로 스크롤 (아트보드 위치는 고정, 이 영역만 내부 스크롤). 넘치면 스크롤 가능함을 그라데이션으로 힌트. 그리드 마지막 칸에 점선 + 타일 배치 — 터치 시 바텀시트 확장. 바텀시트가 확장되면 이 영역 위로 덮임
- **아이템 삭제**: 하단 옷 리스트에서 터치 → 우상단 X버튼 활성화 → 재터치로 삭제 / 아트보드에서 화면 바깥으로 드래그 시 햅틱 + 바깥 영역 딤드 처리 + 휴지통 아이콘 노출, 드롭 시 삭제
- **되돌리기(Undo)**: 직전 동작 취소 지원
- 우상단 V버튼 또는 하단 [코디 만들기] 버튼으로 저장

## 3. 스타일 일지

### 스타일 일지 메인 (Main형)

- 공용 네비게이션 적용 (상단 헤더 컨텐츠 이름 드롭다운 + 좌하단 조건부 뒤로가기)
- 갤러리 형태, 코디/옷장과 동일한 레이아웃 패턴 (그룹화 없이 플랫한 갤러리)
- 정렬/필터
    
    날짜, 옷 종류, 날씨, 계절 기준 지원 (역순 보기 옵션 포함). 진입 시 항상 고정된 기본값(날짜 기준 최신순 · 전체 보기)으로 시작
    — 옷장/코디가 항상 루트(그룹 보기)로 시작하는 것과 동일한 "메뉴 진입 시 항상 고정 상태로 리셋" 원칙을 따름
    
- 우하단 [+] 버튼 → [1카드 추가 / 여러카드에 분할 추가]
- 1카드 추가 시 첫 선택 이미지가 자동으로 대표이미지 지정

### 스타일 일지 추가 (Add/Create형)

- 간단한 이미지 편집기 (비율 선택, 확대/축소, 회전만 — 배경제거 없음)
- 편집 완료 후 열람 화면으로 전환, 코디/옷 정보 바인딩은 열람 화면에서 진행

### 스타일 일지 열람 (Detail형)

- 공용 네비게이션 적용 (상단 헤더 컨텐츠 이름 드롭다운 + 좌하단 조건부 뒤로가기)
- 카드 구조: 대표이미지(1번, 고정) → 코디 슬롯(2번, 고정) → 추가 사진(3번~, 좌우 드래그로 순서 변경 가능)
- 이미지 좌→우 스와이프로 슬롯 간 이동
- 코디 슬롯 미연결 시 반투명 [코디+] 표시, 터치 시 코디 목록 하단 시트로 연결 (신규 코디 생성도 가능, 생성 시 자동 연결)
    - 단, 이렇게 만든 코디 안에서 다시 스타일 일지를 새로 만드는 것은 불가. **선택만 가능**(바인딩 뎁스 제한). 자동 매칭 규칙은 코디 섹션 참고
- 이미지 하단 착용 옷 목록(가로 스크롤) + 우측 끝 [+] 버튼으로 옷 추가
- 날짜/장소 정보 (갤러리 메타데이터 자동 입력, 수정 가능)
- (Phase 2) 메모 필드 (최대 1000자, 공백/개행만 있으면 "내용 없음"으로 간주해 저장 안 함)

## 5. 삭제 & 휴지통 (Main형, 플랫+필터 변형)

**두 가지 다른 "삭제" 개념 구분**

- **연결 해제(Unlink)**: 코디 아트보드에서 옷을 빼거나, 스타일 일지에서 코디 슬롯을 비우는 것.
- **삭제(Delete)**: 옷/코디/스타일 일지 레코드 자체를 지우는 것. 삭제 시스템은 “논리 삭제 → 휴지통 → 영구 삭제” 3단계 상태를 가짐. 아래 규칙 적용

**삭제 진입점**

- 상세 화면(옷 상세/코디 상세/스타일 일지 열람): 헤더의 "⋯"(더보기) 아이콘 → 메뉴에 [삭제]
- 메인 갤러리: 우상단 [선택] 버튼 또는 항목 길게 누르기 → 다중 선택 모드 → 하단 액션바 [삭제]

**동작**: 되돌릴 수 있어 확인 모달 없이 즉시 휴지통으로 이동 + 토스트("휴지통으로 이동됨 · 실행취소")

**삭제 대기 상태**: `is_deleted`플래그만 세팅, 다른 곳 참조는 평소처럼 정상 노출(복원 시 즉시 반영)

**휴지통 화면**: 설정(Settings) 내부에 위치(헤더 드롭다운엔 미포함)

옷/코디/스타일 일지 통합 갤러리 + 필터 칩(`전체 | 옷 | 코디 | 스타일 일지`).

아이폰 사진 앱 "최근 삭제됨"처럼 순수 썸네일 타일 그리드로 표시(리스트 행이 아님).

각 타일에는 유형 표시 아이콘 배지와 "N일"(영구 삭제까지 남은 일수) 텍스트가 썸네일 위 오버레이로 노출

- 우상단 [선택] 버튼 또는 항목 길게 누르기로 다중 선택 모드 진입 → 하단에 [복원] [영구 삭제] 플로팅 버튼 노출
- 화면 상단에 [비우기] 버튼(전체 일괄 영구 삭제) — 가장 파괴적인 동작이라 강한 확인 모달 필요: "전체 {N}개 항목을 영구 삭제하시겠어요? 되돌릴 수 없어요" [취소] [비우기]
- 개별/다중 [영구 삭제]도 일반 삭제와 달리 되돌릴 수 없으므로 확인 모달 필요: "영구 삭제하면 되돌릴 수 없어요, 계속할까요?"

**타일 터치 시 동작**: 다른 Main형 화면과 달리 상세 페이지로 전환되지 않고 **정보 팝업**이 뜸

- 팝업 상단: 컨텐츠 유형 표시(옷/코디/스타일 일지), 우측 모서리 닫기 버튼
- 헤더 아래: 이미지 배치
- 이미지 안쪽 중앙 하단: "N일"(영구 삭제까지 남은 일수) 오버레이
- 헤더-이미지 사이 또는 이미지 아래: 제작된 날짜/시간 표기(삭제일이 아닌 생성일)
- 팝업 하단: [복원] [영구 삭제] 버튼 — 팝업 내용이 길어 스크롤이 생기더라도 이 버튼들은 스크롤 위치와 무관하게 항상 화면 하단에 고정 노출. [영구 삭제] 선택 시 위와 동일한 확인 모달 노출

**자동 영구 삭제**: 15일 경과 시 자동(앱 실행 시 클라이언트 체크, 별도 서버 스케줄러 불필요). 이때 다른 참조는 조용히 제거(고스트 placeholder 없음)

### **옷 삭제 시 코디 캐스케이드 처리**

- 핵심 아키텍처: 코디는 저장 시마다 평면 렌더링 스냅샷 이미지 저장. 목록/상세는 항상 스냅샷 사용(참조 아이템 삭제돼도 안 깨짐). 라이브 데이터 정리는 "편집 진입" 시점에만 발생
- 옷 삭제 시 사용 코디가 1개 이상이면 안내 팝업: "이 옷은 {N}개의 코디에 사용되고 있어요. 삭제하면 휴지통으로 이동하고, 각 코디는 다음 편집 시 자동으로 제거돼요. [취소] [휴지통으로 이동]"
- 코디 목록: 삭제된 옷 포함 코디는 타일에 작은 배지(연결끊김 아이콘, 차분한 톤)
- 코디 상세: 스냅샷 그대로 표시 + 안내 문구("다음 편집 시 자동 정리"), 사용된 옷 목록엔 "삭제됨" 회색 placeholder 칩
- 편집 진입 시: 확인 팝업("삭제된 옷 {N}개 포함, 편집 시작 시 자동 제거") → 진행 시 제거된 채로 진입(즉시 저장+스냅샷 재생성)
- 정리 후 0개 남으면 별도 "빈 코디" 상태 새로 만들지 않고 기존 "미완성" 처리 재사용(예측 가능성+구현 단순성 모두 만족)
