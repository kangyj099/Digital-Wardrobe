[TechDebt] `guard_git_actions.py`가 원본 커맨드 문자열 전체에 정규식 매칭 — 실제 git/gh 호출이 아니어도 오탐 가능

상태: 미해결 (의도적으로 보류)

내용:
`.claude/hooks/guard_git_actions.py`의 COMMIT_RE/PR_CREATE_RE/PUSH_RE/MAIN_TOKEN_RE는 Bash 툴 호출의 원본 커맨드 문자열 전체에 대해 `.search()`를 수행한다. 실제로 git/gh를 호출하는 커맨드가 아니라, 단순히 그 문자열("git commit", "gh pr create", "git push origin main" 등)을 텍스트로 담고 있는 커맨드(예: 문서/테스트 스크립트를 작성하는 heredoc, `python -c` 안의 문자열 리터럴, JSON 페이로드를 echo하는 명령)도 동일하게 차단된다. 근본 해결은 커맨드를 실제로 파싱(예: 첫 토큰이 `git`/`gh`인지, 셸 연산자로 분리된 각 서브커맨드 단위로 판단)해야 하는데 범위가 커서 이번 라운드에서는 보류.

발견 경위:
git-flow 커밋/PR 정책 전환 작업(Task 2) 리뷰 중 리뷰어가 자기 자신의 진단용 Bash 호출(트리거 문구가 포함된 heredoc/one-liner)이 라이브 훅에 의해 차단되는 것을 실제로 재현하며 발견. 같은 라운드의 fix 작업(worker)도 브리프의 검증 커맨드 자체가 라이브 훅에 걸려 직접 실행하지 못하고 코드 리뷰로만 검증을 대체해야 했음.

영향:
- 오탐 시 불편함(정당한 작업이 게이트에 걸림) 수준이며, 안전 방향으로 오탐하는 것이라 보안/정책상 심각한 문제는 아님.
- 이 하네스로 관련 작업을 계속할 때 계속 마주칠 수 있음 — 특히 훅 자체를 다루는 문서/테스트 작성 시.

조치 방향(착수 조건):
비슷한 문제가 반복되거나 작업 여유가 생기면, 커맨드를 셸 연산자(`&&`, `;`, `|`)로 분리한 뒤 각 서브커맨드의 선두 토큰이 실제로 `git`/`gh` 호출인지 확인하는 방식으로 교체 검토.
